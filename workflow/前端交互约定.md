# 前端交互约定

用于新项目的后台列表、表单、配置编辑器和业务处理界面。设计、实现和验收同一类交互时，以本页为默认约定。接入已有产品时，先核对目标页面和同类页面的现行交互，按本次已确认的规则处理差异。

## 列表与检索

| 场景 | 默认约定 |
| --- | --- |
| 操作列 | 固定在表格可见区域最右侧。横向滚动时行操作持续可见、可点击，表头与各行对齐。 |
| 行内容 | 数据行保持单行。不同业务字段各占一列。列表中展示节点、路径等长内容时，先显示能容纳的完整标签，余项用 `+n` 提示并可查看明细，显示范围与计数范围一致。 |
| 分页 | 分页放在表格下方，当前结果总数放在分页行最左侧。 |
| 状态筛选 | 用状态页签切换，贴近搜索区，搜索放在页签右侧。状态可同时展示文字和颜色，页签有数量时用括号显示，统计范围随当前项目定义。 |
| 常规检索 | 一至两个检索对象直接显示紧凑输入框，在框外常显各字段名称。直接通过输入框操作，省去独立的查询、重置按钮。按同类页面约定在回车或输入时执行。清空一项只解除该项条件。 |
| 高级搜索 | 检索对象超过两个时使用可展开、收起的高级搜索。各检索条件与状态页签可叠加，收起面板时保留已生效的条件。无匹配结果时显示空状态。 |

同一业务对象在多个页面出现时，复用已建立的标签、状态、筛选和详情入口。调整交互后检查其他适用页面，例如横向滚动时各列表的操作列是否都固定在最右侧。

## 表单与操作反馈

- **按问题位置反馈。** 必填、长度、重名等字段校验在对应输入框下方显示提示，保留用户输入。保存成功、状态限制等整项操作反馈统一用页面或全屏弹窗右上角提示。能定位到具体配置项时，提示指出待完善项和处理方法。
- **常用操作直接完成。** 保存按当前对象执行。采用全屏编辑且用户要继续工作时，保存后停留在当前窗口并提示结果。复制为新对象用独立入口，沿用新建的字段与校验。允许分阶段配置时，明确草稿保存、正式生效各自的条件和结果。
- **按操作风险决定可用状态。** 用户需要理解限制并继续处理时，可保留入口，点击后说明原因和下一步。规则明确禁止的高风险操作可置灰。删除使用统一的危险操作样式，删除已保存记录、容器及其内容，或批量删除前确认对象和影响范围。画布内节点等局部操作的确认行为按其保存和恢复方式约定。
- **按用户是否可决策决定界面内容。** 固定值、后台管理参数和可由上下文直接确定的取值默认由系统处理。重复说明集中到与操作最相关的位置。控件仅在有作用时显示，例如只有一条条件时无需显示“与／或”，只需要一个操作数时隐藏第二个输入。通用界面使用覆盖全部适用场景的文案，特定业务例子放在对应场景说明里。
- **让批量操作范围明确。** 导出等操作支持不同范围时，用清晰的名称区分勾选记录与全部筛选结果。只有本次存在敏感内容且允许选择处理方式时，展示对应选项。具体脱敏方式和默认选择按项目需求确定。
- **复用名称和操作方式。** 同一概念在不同模块沿用同一个名称，同类输入的布局、模式切换、拖放和校验反馈保持一致。多处控件修改同一份设定时，任何一处修改后同步展示结果。

## 流程与字段配置器

适用于需要从上游选取数据、编辑参数并确认输出结构的界面。

1. 左侧展示可用输入，中间放当前配置，右侧展示输出结构。各栏可在内容超出时分别滚动。缺少输出的步骤保留布局，输出栏呈现为空。输出结构根据配置更新，固定产物用固定名称展现，内部确实可变的字段再提供配置。
2. 来源按上游步骤分组，显示字段名、类型和层级。默认展开直接前序来源，其他来源收起，允许反复展开和收起。当前配置没有提供的数据类别从可选项中省去。已提供的来源字段保留原有层级，根据当前可绑定的位置区分可拖拽和不可拖拽字段，统一使用本项目的可用和置灰样式。
3. 拖入绑定位置使用普通输入框，空时用简短占位提示，聚焦仍是普通输入框行为。拖动时显示被拖字段，进入兼容区域高亮并提示可松开。拖不到目标或类型不兼容时保留现有值并给出相应反馈。模型提示词、代码等长文本仍支持直接编辑和在目标位置插入字段引用，使用同一种提示方式。
4. 绑定结果可看到来源，长路径可按需查看，已选绑定可清除或替换。来源重新命名时，已有绑定仍有效。来源或类型变化导致不可用时，保留选择并指出原因，恢复兼容后重新校验。后台记录用于定位的稳定标识，界面使用用户熟悉的名称和路径。

## 查看过程与人工审核

- **查看过程。** 查看某次处理时，呈现选中记录实际收到的输入和实际产生的输出，输入在上、输出在下。按字段和字段值展示，集合逐项查看，长内容在所在区域右下角展开或收起。面向业务用户预览时，优先用可读的字段、文本或文件内容。查看过程作为只读入口，实际处置走对应待办入口。
- **对照审核。** 需要并排核对较长内容或文件时用全屏窗口，左侧呈现待审内容，右侧呈现原始对照。有多种对照资料时，可在右侧通过页签切换，默认显示当前审核最常用的对照。同一条记录有多类待办时，在同一窗口通过页签切换，仅展示本次实际可审核的类别。审核原因放在类别页签下方，随当前待办更新，用业务语言说明触发原因。提交并下一条按当前类别处理，更新本次提交涉及的待办。
- **来源预览。** 从来源链接打开用户想核对的实际内容，例如从记录题名进入原文预览。来源包含多个文件时提供可识别的文件选择，切换时同步更新预览和对应说明。

## 应用与更新

1. 新项目在开始画原型前，挑选本次涉及的界面类型，参照约定决定共用组件和验收入口。业务状态、统计口径、字段、权限及数据处理结果写入本项目需求，按实际业务确认。
2. 用户新增或纠正交互时，先按最新确认更新当前项目对应的规则、示例和验收条件。明确适用对象及生效条件。涉及多个同类页面时，同时核对共用组件和受影响入口。
3. 用户明确适用于以后项目，或同一偏好已在多个适用场景确认时，在公共工作流的本页维护对应条目，写清适用范围、例外和可验收行为，随框架版本分发。若正在业务项目工作，先在 PROJECT.md 记录适用范围和通用变更，再按公共仓库的维护权限同步。单个项目的业务取舍保存在该项目的需求资料中。
4. 以目标预览入口核对结果。列表检查横向滚动、条件叠加和清空、分页及空态。表单检查失败时保留输入、成功反馈及重新打开后的数据。配置和审核界面检查拖放反馈、来源变化、多类别或多文件切换。同步核对正式需求的功能项、文字、示例和交付版本。
