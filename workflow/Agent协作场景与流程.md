# 产品项目协作场景与流程

主 Agent 根据用户需求确定交付类型和完成标准，复用有效资料与验证证据。需要新设计判断时集中交 product，具备完整验收条件时交 qa。每个场景按项目实际授权开展。

## 1. 需求梳理与业务规则

主 Agent 核对用户输入、已有资料与业务对象，整理目标、用户角色、流程、范围和完成标准。出现核心规则冲突或重要交互取舍时，由 product 集中分析方案及影响，主 Agent 按授权处理并落稿。

需要用户决定时提出简短的具体问题，确认后更新正式规则。已有规则使用草稿、待确认、已确认标记。

完成条件为用户需求可逐项对应到规则、交付物或明确待定项，资料中的对象、状态、权限与范围一致。

## 2. 业务与竞品调研

主 Agent 围绕本次需求明确待查问题，查阅项目资料和可核验来源，记录来源日期、对象版本与相关事实。将观察事实、推断和建议分别表达，说明参考方案在本项目中的适用条件。

涉及产品取舍时交 product 集中评审，主 Agent 将采用的结论纳入对应规则。常规资料查找与汇总由主 Agent 完成。

完成条件为调研回答了本次问题，重要结论能追溯到依据，建议具有适用范围。功能介绍、实际体验和运行验证各自记录覆盖。

## 3. PRD 与需求文档

主 Agent 依据用户指定结构、团队规范和已确认方案编写文档，覆盖相关页面、字段、操作、规则、提示、状态及异常路径。修改已有文档时保留适用的原文和编号，集中修改本次需求涉及的内容。

新规则或交互冲突由 product 评审。完整 PRD 阶段按范围安排 qa 核对来源需求、原型与文档，修复遗漏和矛盾后复验。既定文档的常规整理与格式维护由主 Agent 自检。

完成条件为需求覆盖可追溯，规则具备可执行的判定条件，示例与正文一致，链接、编号及表格可用。用户要求的 Markdown、HTML 或其他格式分别检查实际交付文件，目标平台效果按实际验证登记。

## 4. 交互原型与界面演示

主 Agent 核对目标用户、业务路径、数据来源和交付范围。新交互或视觉方向由 product 集中评审，形成可复用规范后，由主 Agent 连续完成页面及交互。

完整功能路径具备验收条件后，qa 从实际入口检查操作、反馈、导航、空态、错误态和支持的尺寸。共用组件先集中检查，后续页面验证接入，最后补查跨页面状态与衔接。

例如审批原型应核对提交、待处理、处理结果及返回列表后的显示。数据与状态的实现程度按本次演示范围记录。

完成条件为已授权的用户路径可操作，页面与需求一致，实际可用能力、演示数据及验证缺口有准确记录。

## 5. 功能实现与系统集成

主 Agent 核对已确认规则、接口和现有实现，在任务范围内开发并自测。新的设计冲突交 product，完整功能阶段交 qa 独立验收。

qa 按相关角色和入口验证正常流程、权限、异常、数据一致性及回归影响。涉及导入、批处理或共享状态时覆盖部分失败、重复提交、重试及历史数据。

完成条件为实际入口满足验收标准，现有调用路径和支持的数据得到覆盖，所用版本、环境和证据可定位。

## 6. 用户反馈与缺陷修复

主 Agent 收集版本、输入、连续操作和日志，对照规则复现。明确缺陷直接修复并自测，预期行为存在分歧时交 product，复杂触发链可提前交 qa 调查。

相关修复形成完整集合后，qa 按原路径及影响范围复验。未复现项登记已查路径、证据缺口和后续采集入口，独立的已授权事项继续推进。

完成条件为已修复问题具有触发条件及前后证据，待核实问题有明确缺口，需求文档、原型及实现中的相关变化同步完成。

## 7. 批量交付与导出

主 Agent 明确清单、规格、命名和验收标准，新类型交付物按需请 product 评审样稿。规范确定后连续制作，逐批检查数量、格式、完整性及映射。

完整交付阶段交 qa 验收，全量核对可量化指标，按类型和风险抽查视觉及内容质量。发现系统性问题时扩大检查范围，修复后复验。

完成条件为实际交付文件满足约定，导出后的表格、图片、链接和内容可用，抽检、全检及目标平台检查范围有记录。

## 8. 变更、同步与接续

用户调整需求后，主 Agent 更新目标、范围、完成标准及相关资料，复用仍有效的证据。需要新的设计取舍时按实际问题交 product，具有运行变化的交付按影响安排 qa。

同步代码或换环境前检查分支、未提交改动、工具、配置和资料完整性。公共框架更新按其版本说明合并，完成引用和实际变化的核对。

用户要求暂停时记录已完成内容、未完成项和恢复入口。完成条件为新会话能够定位项目版本、已确认规则、验证缺口及用户指定的下一项工作。
