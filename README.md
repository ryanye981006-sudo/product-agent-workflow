# 产品项目 Agent 工作流

面向需求梳理、业务调研、PRD、交互原型和产品实现的可复用协作流程。用户提出需求后，主 Agent 持续完成授权范围内的整理、调研、制作、验证和记录，product 提供集中设计评审，qa 提供阶段验收。

当前工作流版本为 `0.2.6`。

## 使用方式

将以下指令交给目标项目中的 Agent，即可按[接入与更新](接入与更新.md)完成接入。已有项目先核对现有协议和项目资料，再合并入口。

```text
请将我指定的产品工作流版本接入当前项目。使用本地仓库时按指定提交读取，使用 GitHub 仓库 ryanye981006-sudo/product-agent-workflow 时按已发布标签读取。
读取仓库中的接入与更新.md，按其中的文件映射安装公共流程并合并项目入口。
根据当前项目资料填写项目概况，保留已有需求、状态、待办和专属约束。
完成文件引用和配置检查，记录采用的版本与验证范围。
```

后续更新时可以这样要求项目 Agent。

```text
请检查 product-agent-workflow 的新版本，按接入与更新.md 更新当前项目采用的公共流程。
对照已安装版本合并差异，保留项目资料和本地定制，完成检查后记录版本与结果。
```

## 项目中的工作方式

1. 用户提出需求，Agent 核对项目概况、当前状态、待办及实际资料。
2. 明确交付物、约束和可观察的完成标准，登记本次任务。
3. 按需要完成调研、需求细化、文档、原型或实现，遇到实质设计问题时调用 product。
4. 完成自检，在完整交付阶段按任务安排 qa 验收，修复并复验实际问题。
5. 更新正式资料、待办与状态，继续完成本次授权内依赖满足的工作。

需要用户决定时，使用简短追问。使用卡片时，将互不影响的问题放在同一张决策卡片中，一题一个页签（tab）。问题聚焦具体选择及其影响，用户确认后同步相关资料。

提问后继续处理独立工作。没有可推进的事项时静默等待，用户回复即继续；从提问起满 5 分钟仍未收到答复时，简要说明进度和待决定事项。

## 文件维护

公共流程安装在目标项目的 `.agent-workflow/`。项目自己的 `AGENTS.md`、`PROJECT.md`、`PROJECT_STATUS.md` 和 `BACKLOG.md` 由该项目持续维护。Codex 配置按现有环境合并。

本仓库包含通用产品流程及 Codex 角色样例。实际角色加载与完整协作效果应在目标项目中验证，验证入口见[配置与接续](workflow/Agent配置与接续.md)。
